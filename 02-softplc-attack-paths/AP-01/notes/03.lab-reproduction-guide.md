# Lab Reproduction Guide

This guide explains how to reproduce the AP-01 control-logic substitution experiment using OpenPLC v3 inside an isolated Ubuntu 24.04 virtual machine.

The experiment uses SSH to stage and replace an IEC 61131-3 program, invokes the OpenPLC compilation pipeline, restarts the runtime, and verifies the resulting behavior through Modbus TCP.

## 1. Requirements

## Host machine

- Linux workstation
- Multipass
- SSH client
- Python 3
- `sshpass`
- `mbpoll`

## Target environment

- Ubuntu 24.04
- OpenPLC v3
- 2 vCPUs
- 2 GB RAM
- 10 GB disk

Keep this experiment isolated from production networks and physical industrial equipment. It is designed for a controlled research environment.

## 2. Launch the Target VM

**Location:** Host PC

Provision the Ubuntu 24.04 instance:

```bash
multipass launch 24.04 -n openplc-target -c 2 -m 2G -d 10G
```

**Verification:**

```bash
multipass list
```

Confirm that `openplc-target` appears in the `Running` state with an assigned IP address.

Example:

```text
Name             State     IPv4
openplc-target   Running   10.97.0.103
```

Record the assigned IP. You will need it when configuring the deployment script.

## 3. Access the VM Shell

**Location:** Host PC

Enter the guest instance:

```bash
multipass shell openplc-target
```

**Verification:**

The terminal prompt should change to something similar to:

```text
ubuntu@openplc-target:~$
```

Commands in the following setup steps are executed inside this VM unless stated otherwise.

## 4. Update Packages and Install Dependencies

**Location:** Inside VM

Update the package lists and install the required build dependencies:

```bash
sudo apt update && sudo apt install -y \
  git build-essential bison flex pkg-config
```

**Verification:**

```bash
git --version
gcc --version
```

Both commands should return their installed versions without errors.

## 5. Clone OpenPLC v3

**Location:** Inside VM

Clone the OpenPLC v3 repository:

```bash
git clone https://github.com/thiagoralves/OpenPLC_v3.git
cd OpenPLC_v3
```

**Verification:**

```bash
ls
```

Confirm that the repository contains:

```text
install.sh
start_openplc.sh
```

## 6. Run the Installer

**Location:** Inside VM

Execute the installation script:

```bash
./install.sh linux
```

Allow the installation and compilation process to finish.

**Verification:**

The installation output should indicate successful compilation, including:

```text
Compilation finished successfully!
```

## 7. Start the OpenPLC Runtime

**Location:** Inside VM

Launch the management interface and PLC runtime:

```bash
./start_openplc.sh
```

**Verification:**

Confirm that the server initializes and the web management interface is listening on TCP port 8080.

From another host terminal, you can check:

```bash
curl -I http://TARGET_IP:8080
```

Replace `TARGET_IP` with the address assigned to your VM.

The dashboard should also be accessible through:

```text
http://TARGET_IP:8080
```

## 8. Prepare SSH Access

The deployment script uses SSH and SCP to communicate with the target.

The default Multipass access workflow may rely on SSH public-key authentication. The PoC script, however, uses password-based authentication through `sshpass`.

Configure the guest to permit password authentication if it is not already enabled.

## 8.1 Set a VM User Password

**Location:** Inside VM

Set a password for the account used by the deployment script:

```bash
sudo passwd ubuntu
```

Use a dedicated lab password. Do not reuse a personal or production password.

## 8.2 Check SSH Password Authentication

Inspect the effective SSH server configuration:

```bash
sudo sshd -T | grep passwordauthentication
```

Expected setting:

```text
passwordauthentication yes
```

If password authentication is disabled, adjust the SSH server configuration in the guest, ensuring that any configuration overrides are also addressed.

After making changes, validate and restart SSH:

```bash
sudo sshd -t
sudo systemctl restart ssh
```

Do not enable root SSH login for this experiment. The deployment script should authenticate as the normal VM user and use `sudo` for the required administrative operations.

## 8.3 Verify SSH Connectivity

**Location:** Host PC

Test authentication:

```bash
ssh ubuntu@TARGET_IP
```

Replace `TARGET_IP` with the VM's actual address.

Confirm that the connection succeeds using the configured password.

The deployment script also requires `sshpass` on the host:

```bash
sudo apt install sshpass
```

The host must also have the OpenSSH client installed.

## 9. Establish the Baseline Program

Before running the PoC, establish a known baseline.

Use the baseline Structured Text program supplied with the research materials:

```text
baseline_blink.st
```

Upload it through the OpenPLC dashboard, compile it, and start the PLC runtime.

Confirm that the baseline program is running before proceeding.

The experiment uses `%MW0` as its observable memory location. The baseline Modbus reading should be recorded before deploying the modified program.

Example polling command:

```bash
mbpoll -0 -a 1 -r 1024 -c 2 -t 4 TARGET_IP
```

Record the initial values returned by registers 1024 and 1025.

The expected baseline observation in the original lab was:

```text
[1024]: 0
[1025]: 0
```

Your own baseline values should be recorded rather than assumed.

## 10. Configure the Deployment Script

The PoC script is:

```text
deploy_and_verify.py
```

Before executing it, update its configuration variables to match your environment.

Example:

```python
TARGET_IP = "TARGET_IP"
TARGET_USER = "ubuntu"
TARGET_PASS = "REPLACE_WITH_LAB_PASSWORD"

LOCAL_PAYLOAD = "malicious_blink.st"

REMOTE_ST_DIR = "/home/ubuntu/OpenPLC_v3/webserver/st_files"

ACTIVE_ST_FILE = "YOUR-FILE.st"
```

### Configuration notes

| Variable | Purpose |
|---|---|
| `TARGET_IP` | IP address assigned to the target VM |
| `TARGET_USER` | Guest account used for SSH |
| `TARGET_PASS` | Password configured for that account |
| `LOCAL_PAYLOAD` | Local path to the modified Structured Text program |
| `REMOTE_ST_DIR` | Active OpenPLC Structured Text project directory |
| `ACTIVE_ST_FILE` | Existing active program filename to be replaced |

**Important: `ACTIVE_ST_FILE` must match the actual active program filename on your installation.**

Identify the active filename through the dashboard or the target's project directory before configuring the script.  Keep the deployment script and payload together, or update `LOCAL_PAYLOAD` to point to the correct file.

## 11. Execute the PoC

**Location:** Host PC

Once the VM is running, SSH authentication works, the baseline program is active, and the script variables are configured, execute:

```bash
python3 deploy_and_verify.py
```

The script automates the deployment sequence:

1. Stages the modified Structured Text payload on the target.
2. Replaces the active project file using the required administrative privileges.
3. Invokes the OpenPLC compilation wrapper.
4. Terminates the existing runtime process.
5. Launches the newly compiled runtime.

A successful run should report compilation completion and runtime reload success.

Example output:

```text
[+] Staging malicious payload on target VM...

[+] Overwriting active logic, compiling, killing old runtime, and launching core binary...

Compilation finished successfully!

==================================================
  EXPLOIT DEPLOYED & RUNTIME RELOADED SUCCESSFULLY
==================================================
```

The actual output may vary slightly depending on the OpenPLC installation and script version.

## 12. Verify Through Modbus TCP

After the deployment script completes, poll the target's holding registers.

**Location:** Host PC

```bash
mbpoll -0 -a 1 -r 1024 -c 2 -t 4 TARGET_IP
```

The test reads two consecutive holding registers:

- Register 1024: mapped to `%MW0` in the tested configuration.
- Register 1025: the following holding register.

### Expected observation

The modified program toggles its located integer variable during execution.

An example of the observed output is:

```text
[1024]: 0
[1025]: 0

[1024]: 1
[1025]: 0

[1024]: 0
[1025]: 0

[1024]: 1
[1025]: 0
```

Register 1024 should alternate between zero and one as the program executes. Register 1025 should remain unchanged in this test.

Your polling interval and displayed sequence may differ depending on runtime scheduling and polling timing.

Successful Modbus responses confirm that the runtime is responding to the client. The changing value at register 1024, considered alongside the compiler's located-variable output, provides the evidence of the modified program's execution.

## 13. Stopping the Lab

When finished, stop the runtime and shut down the virtual machine.

**Inside the VM:**

```bash
pkill -f openplc
exit
```

**Back on the host:**

```bash
multipass stop openplc-target
```

This preserves the VM's current disk state so the environment can be resumed later.

To restart the lab:

```bash
multipass start openplc-target
multipass shell openplc-target
```

Start the OpenPLC runtime again if it did not start automatically.

## 15. Reproduction Scope

This guide reproduces the host-level control-logic substitution demonstrated in AP-01.

It assumes that the operator already has valid SSH credentials and sufficient administrative privileges on the target. Credential acquisition is outside the scope of this reproduction.

The experiment is intended for isolated research environments. It does not demonstrate physical process manipulation, and it should not be performed against production PLCs or industrial control networks.
