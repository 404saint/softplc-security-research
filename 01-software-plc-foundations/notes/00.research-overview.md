# 00. Research Overview

## 1. Introduction

Software PLCs implement programmable logic controller functionality through software running on computing platforms such as industrial PCs, virtual machines, and containerized environments.

Although their purpose remains the same as traditional PLCs, their underlying architecture introduces different relationships between the control application, runtime, operating system, hardware, and supporting services.

Understanding these relationships is important when assessing how software PLCs operate, how they interact with industrial processes, and where security boundaries exist.

This research establishes a technical foundation for understanding software PLC architecture, deployment, execution, engineering workflows, and security considerations.

## 2. Research Scope

The research examines six interconnected areas:

1. **Physical PLCs and Software PLCs:** Establishes the architectural differences and common characteristics between traditional hardware-based controllers and software-based implementations.

2. **Software PLC Deployment Models:** Examines how software PLCs operate across native hardware, operating systems, virtual machines, containers, and edge computing environments.

3. **Industrial Control Logic and Programming Languages:** Explores how control behavior is represented through IEC 61131-3 programming languages, variables, functions, function blocks, and application organization.

4. **PLC Program Execution:** Examines how applications are loaded, initialized, scheduled, and executed, including input acquisition, output updates, and execution timing.

5. **PLC Engineering and Program Lifecycle:** Covers application development, compilation, transfer, online monitoring, modification, version management, backups, and recovery.

6. **Software PLC Security Boundaries:** Establishes the trust relationships between the host environment, runtime, engineering workstation, control application, management interfaces, and industrial network.

Together, these investigations provide an architectural understanding of software PLC environments, from their underlying computing platforms to the execution and management of control applications.

## 3. Architectural Perspective

A software PLC is not simply a control application running on a computer. It is an interconnected environment in which hardware resources, operating systems, runtime services, engineering tools, application logic, and industrial interfaces work together.

Its deployment model influences how computing resources are allocated and isolated. Its programming environment determines how control behavior is represented. Its runtime manages the execution of that behavior and coordinates interactions with the industrial process.

The engineering environment provides the means to develop and maintain applications, while the underlying deployment architecture determines the boundaries between trusted components and external systems.

These relationships provide the context needed to understand both the operational characteristics and security considerations of software PLCs.

## 4. Research Approach

The research primarily uses technical documentation, academic publications, industrial standards, and credible industry resources.

OpenPLC Runtime v4 is used as a practical reference where implementation-level context is useful. Existing lab observations support selected architectural discussions without making OpenPLC the exclusive subject of the research.

Findings are distinguished according to their evidence:

- **Documented behavior:** Characteristics described in official documentation, standards, or technical publications.
- **Lab observations:** Behavior directly observed in the existing experimental environment.
- **Technical interpretation:** Analysis derived from documented architecture and observed behavior.

Laboratory validation is selective and used where it adds practical value to the investigation.

## 5. Outcome

The research establishes a foundation for understanding software PLC environments as complete control systems rather than isolated runtime applications.

It connects the computing platform, deployment architecture, control logic, execution model, engineering lifecycle, and security boundaries into one architectural perspective.

This foundation provides the context for subsequent practical investigations into software PLC security.
